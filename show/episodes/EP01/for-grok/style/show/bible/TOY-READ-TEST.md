# #35 — TOYETIC DESIGN CONSTRAINTS → toy-read test for the design gate

**What was studied.** Toyetic design as documented practice in
creature-franchise production: a design is toyetic when it
survives translation to a physical object a child holds —
which imposes testable constraints long before any toy exists:
the silhouette must read at palm size, the colour blocking
must survive moulded-plastic simplification (few, large colour
regions), there must be no fragile/thin features that a mould
or a drop destroys, and the face must read at arm's length.
These are *tests on the design*, not a merch programme — no
toy line is canon, and none is proposed here.

## The test — proposed gate addition G-13 (TOY-READ)

Status: **PROPOSED** — written for adoption into the Design
Gate set (DESIGN-THEORY G-1..G-12 is the master gate; this
package cannot amend it unilaterally). Until adopted, it runs
as a *reported* check in batch production (PROCESS.md step 4
companion), pass/fail recorded in the manifest, never blocking.

A design passes TOY-READ when all four hold:

1. **Palm read** — the approved silhouette test (G-1/G-2)
   still identifies the species at 25 mm print height (the
   existing 32px test is the screen proxy; this is its
   physical twin — same art, smaller, printed)
2. **Colour-block count** — the design's flat colour fields
   (Mochiichao Style Spec: 2–3 mains + 1 accent) number **≤5
   large regions** at toy simplification: any field that would
   vanish or merge in moulded plastic is counted merged, and
   the merged read must still identify the species
3. **No fragile reads** — no *identifying* feature depends on
   a thin spike/appendage/antenna thinner than ~8% of body
   width at palm scale (such features may exist as flavour —
   Kittember-class tails, fins — but identity may not *rest*
   on them; if the thin part broke off the toy, it must still
   be recognisably the species). Wispkin's mask crack is a
   protected balance flaw (canon), not a fragile read: a crack
   is printed/moulded *in*, it cannot break *off* — recorded
   here so the test is never misapplied to it.
4. **Face at 2 m** — the face (eye construction + one
   expression instrument) identifies the species' temperament
   class at 2 metres on the printed proof — the shelf-distance
   version of the fight-read test; a face that only reads as
   generic-cute at distance fails here even if it passed
   fight-read at full size (the two tests are cousins, not
   duplicates: fight-read asks *can it battle*, toy-read
   asks *can it be recognised across a room*).

## Wiring

- **Design gate set** — proposed as **G-13** beside G-1/G-2
  (the other scale tests); adoption is an owner/board act,
  recorded in the gate doc when it happens.
- **Batch production** — PROCESS.md step 4 gains the four
  checks as a reported block per design (manifest field
  `toyRead: {palm, blocks, fragile, face2m}`), so the data
  exists from the first batch run under this spec whether or
  not G-13 is adopted.
- **Card line (#36)** — a design that passes toy-read is the
  same design whose card art crops safely (shared silhouette
  discipline); no data is shared, the *design property* is.

## Coverage — honest

- **Practice: documented** at the level of production craft
  writing on toyetic design; there is no single public
  standard document, so the four checks are this project's
  formalisation — labelled PROPOSED throughout, thresholds
  (25 mm, ~8%, 2 m) are working values for the board to tune,
  not canon and not industry law.
