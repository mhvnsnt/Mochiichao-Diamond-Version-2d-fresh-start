# #347 — THE CONSCIENCE PROMPT FAMILY → which acts stop and ask, and which never do

**The seed is already law.** List 28's owner
addendum (in #268's file, beside #269's note)
founded the first conscience prompt: throwing a
capture device at an owned Mochi in a Ranger battle
asks first — **"Are you sure you want to try and
steal this person's Mochi?"** — and backing out is
free and writes nothing. This spec builds the
*family* that one prompt belongs to: the taxonomy
of which acts in this game earn a confirmation,
what shape every prompt in the family takes, and
— just as binding — which acts never prompt at
all. The addendum is cited, not rebuilt; this is
the general law it turns out to have started.

## Native spec — `mochiichao/conscience-prompt/v1` (fragment beside this doc)

- **The taxonomy — an act prompts when it is BOTH
  morally loaded and hard to undo.** Closed classes
  (membership is by class, never by a designer's
  mood at the content pass):
  - **Taking what is someone's.** Any snag-class
    throw at an owned target (#268's gate — the
    family's founding member). Includes re-snag
    shapes by target read, not by intent: the
    device cannot know you mean well, so it asks
    by what the target *is* (owned / closed-heart,
    #349) — intent is settled by the answer and
    the record, never by a pre-reading of the
    player's heart.
  - **Letting go of a bond.** Releasing a Mochi
    whose accrued bond (#39's ledger) stands above
    the high-bond threshold (data, tuned at
    landing) prompts before #211's farewell runs —
    the release of a near-stranger does not prompt;
    the release of a friend asks once. (Release
    itself stays lawful and unpenalised — #267's
    world: the released individual walks back into
    the wild. The prompt guards the *accident*, not
    the act.)
  - **Breaking a trust in progress.** Abandoning a
    #245 rescue mid-act — after custody of a hurt
    individual has been taken (#245's chain), before
    its outcome — prompts: you are holding someone
    who cannot finish the journey alone, and
    putting them down is a recorded choice, not a
    menu slip.
  - **Betrayal-class takings generally.** Any future
    act the deed ledger (#269) scores as a taking
    from a specific keeper enters this family by
    that scoring — the taxonomy is keyed to the
    ledger's vocabulary, so a new dark deed cannot
    slip in unprompted by being new.
- **What NEVER prompts — flow is a value.** Ordinary
  capture of wild targets, ordinary battle commands,
  trades and gifts at their own consent doors
  (#168/#217 — consent is already their shape, and
  a second prompt on top of consent is noise),
  releases below the bond threshold, healing, care,
  travel, purchases. A prompt that fires on ordinary
  play trains the player to mash YES, and a mashed
  YES is the death of the whole family: the prompt
  only means something because it is rare. Any
  proposal to add a prompt outside the taxonomy
  above is a proposal into this file, argued against
  this paragraph.
- **The shape — a beat, not a dialog tree.** Every
  prompt in the family is: one question, two
  answers, nothing else. No sub-menus, no "are you
  really sure" second stage, no cost preview beyond
  what the question itself says, no timer. YES runs
  the act exactly as its own system specifies it.
  NO cancels the input **whole** — no item consumed,
  no turn spent, no deed written, no record of the
  asking (the #268 addendum's law, generalised).
  Hesitation is not a deed; the ledger never learns
  that a prompt was shown and refused.
- **Copy is data.** Prompt strings live in #23's
  string layer as ordinary display data, one string
  id per prompt class, so wording can be translated
  and tuned without touching mechanics. The steal
  line itself is **owner-drafted** (2026-10-27) and
  lands verbatim; the other classes' lines are
  writing, drafted in the same plain register (the
  fragment carries shapes, not final copy, for
  those). A prompt's string may state the plain
  fact of the act; it may never editorialize beyond
  the owner's register — no scolding, no pleading:
  the question is the conscience beat, and the
  player's answer is theirs.
- **Who is never prompted.** NPC acts never prompt
  (#268's addendum: the gate is on the player's
  input; an NPC's theft is an event the player
  suffers, not a choice anyone confirms). Versus
  contexts inherit #268's lobby exclusion — where
  the act itself is forbidden, there is no prompt,
  because there is no act.

## Show lane

The show has no prompts — nobody asks the audience.
But the conscience beat is a staging shape the show
steals wholesale: the held moment before a theft
throw, the hand that stops (#355 carries the
staging). A hero's hesitation and a villain's lack
of it are the same beat played two ways (#276).

## Wiring

Gate mechanics: #268 (the founding member, landed
as the List 28 addendum). Bond threshold read: #39
(over #211's release flow). Rescue custody state:
#245. Deed-vocabulary keying: #269 (a taking scored
there is a prompt class here — the join is a
validation rule, STAGING step 2). Strings: #23.
Never writes: a prompt-shown record, a declined-act
deed, a hesitation flag of any kind.

## Open slots

The non-steal prompt strings' final wording
(writing, in #23's data — the steal line is the
owner's and closed) · the high-bond release
threshold value (system data, tuned at landing
beside #39's scale). No mechanic is parked, and no
story fact is opened by this spec.

## Coverage — honest

- Taxonomy and shape: fully specified, generalising
  one landed member (#268's gate).
- Contents: one prompt string exists (the owner's);
  the family's other classes are shapes awaiting
  their lines — writing, not design.
