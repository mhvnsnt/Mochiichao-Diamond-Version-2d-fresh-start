# #74 — LICENSING STYLE-GUIDE STRUCTURE → Mochiichao brand guide format

**Teardown (public documentation).** A licensing/production style
guide — the document licensees and partner studios actually work
from — has a stable published structure (visible across studio
guide excerpts, licensing-trade literature, and brand-guideline
practice generally): (1) **brand core** (what the property is, its
audience promise, the world in one page); (2) **character guide** —
model sheets, turnarounds, scale charts, expression/pose sets,
**do/don't pages** (the most-used pages in any guide: the character
drawn wrong on purpose, labelled); (3) **logo & typography** (marks,
clear-space, lockups, typefaces); (4) **colour** (palette with
values, per-character colourways, variant rules); (5) **environments
& props** (key locations, recurring props, signage language);
(6) **packaging/product application** (how the art sits on goods —
the design-gate's toy-read/plush outputs feed here); (7) **voice &
language** (how characters speak/are written — for us: cries-only
law, subtitle law, house writing system); (8) **legal/credits**
(credit lines, copyright notices, approval process). The kit taken
is the *table of contents and the do/don't discipline* — no guide
content, art, or text from any property is copied; every page of
ours is filled from Mochiichao canon or marked OPEN.

**Native format — the Mochiichao Brand Guide (chapter map).** The
guide is an **assembly document**: each chapter points at the
canonical in-repo source that already governs its subject, so the
guide can never drift from production truth — it *indexes* the law,
it does not restate it. Where no source exists yet, the chapter is a
named OPEN slot, not a hole someone fills from memory.

| Ch. | Chapter | Canonical source (input) | Status |
|---|---|---|---|
| 1 | Brand core / world in one page | Season canon map + show bible | ASSEMBLE at landing |
| 2 | Character & creature art | **MOCHIICHAO STYLE SPEC** (species-art/new-gens/) + canon cutouts + model sheets | Source exists — the Style Spec is *this chapter's art-grammar input*, one input among the guide's eight chapters |
| 3 | Logo & typography | Repo font assets (17 font files) + title treatment | OPEN — no logo lock on record; never invent a mark in the guide |
| 4 | Colour | COLOR-SYSTEM v2 (incl. Lustre Law, #a03436 law) | Source exists |
| 5 | Environments & props | Parts catalog + LIVING-WORLD location canon (Gate/Pond/Green/Dark Forest) | Sources exist |
| 6 | Product application | Design-gate toy-read + plush spec (List 3 #25); packaging spec (List 6 #54) | Sources exist as specs |
| 7 | Voice & language | Voice law (cries only), subtitle law, house writing system, prosody system | Sources exist |
| 8 | Credits & approvals | Credits format (List 3 #26) + WORKING-METHOD (construction-kit rule) | Sources exist |

**The do/don't discipline (the chapter-2 pages that matter most).**
Each principal species gets a don't page built from *our own gated
failures*, which are already documented: detached Kittember flame
(fail — flame is tail-tip, canon), glossy-3D finish (fail — the
rejected batch precedent), preschool soft render (fail — batch-001
verdict), baked shadows (fail — standing law). Don't pages use the
rejected artifacts themselves as the labelled examples — the guide
teaches from the studio's real gate history, which no outside guide
could give us.

**Currency law hook.** The guide follows the current-version law:
each chapter names its source's current version; when a source is
upgraded, the guide entry updates in the same landing. A guide that
points at a superseded plate is a regression with extra steps.

**Wiring.** Consumes: Style Spec, COLOR-SYSTEM, parts catalog,
voice/subtitle law, credits format, WORKING-METHOD. Consumed by:
#76 web export (public presentation rules), any future licensing,
and the design gate's style checks (the guide is the human-readable
front door to laws the gates already enforce mechanically).

**Coverage.** Structure: standard and fully documented. Contents:
chapter map complete; ch. 3 (logo/type lock) is genuinely OPEN —
flagged, not filled. Assembly of the guide document itself is a
landing-lane task once ch. 3 is ruled.
