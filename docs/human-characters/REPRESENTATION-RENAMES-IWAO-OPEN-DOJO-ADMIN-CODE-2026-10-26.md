## A. Renames — anime/cartoon research, based on canon, not random

### How the names were built (pattern, not copying)
JoJo / Bleach / Naruto-style naming, as a pattern, works three ways, and all three were used here:
1. **Sound first, meaning second.** A name that sounds like the character's job or weapon (a broker sounds smooth and slippery; a mechanic sounds short and percussive; a cook sounds warm and round).
2. **One visual motif carried in the name.** Pale hair, a violet coat, a serpent bracelet, a wrench, a spice — one motif, never the whole character summed up in the name.
3. **A given name + a working surname that is not a famous character's full name.** No proposal below is the full name of an existing anime/cartoon character, and none is a Pokemon name. If any option rings a bell for Mars, veto it — a name that reminds him of another character is a failed option, even if the full name is not an exact match.

Riku Hayama ("Dash", hard-worker fighter) is NOT changed, per the order. Keep as is.

## C. Admin structure in Pokemon code — plain prose explanation

### What Pokemon code actually has (and does not have)
There is **no "admin hierarchy" table in any of the three decomps**. Pokemon never wrote a data structure that says "this faction has 10 admins, 2 per region, plus 2 roving". What the code has is three smaller pieces, and the hierarchy is what the player feels when those pieces are combined:
1. **A trainer class per rank.** A class is a job title with a sprite, a nameplate style, and an AI level. Grunts get a grunt class; an executive gets their own class, not a grunt class with a flag; the boss gets a boss class.
2. **A trainer record per encounter.** One record = one fight: class, name, party (species + levels + items + moves at higher ranks), money/reward, AI flags, and message slots (intro / lose / after, and in Black 2, win). A rematch is a *second* record with the same class and a `_2` suffix, not a flag on the first record.
3. **World flags that hide and show people.** Beating an admin sets a flag; the flag hides that admin's overworld sprite, opens a door, or makes the next admin appear. The hierarchy is a chain of flags, not a tree in a file.

If you look for a single "admins = 10" table in Pokemon code, you will not find it, because Pokemon never needed one — each game has one region and one faction, so the admins are just a handful of named records placed by hand.

### The three decomps, file by file (structure only, no names/cries/dialogue shipped)
- **FireRed** (`pokefirered-leafgreen/src/data/trainers.h`, `src/data/trainer_parties.h`): a trainer record is a struct with `.trainerPic` (the sprite, separate from the party), `.party` (a list of species/levels), and a trainer class constant. Faction leaders get their own `TRAINER_PIC_*` (e.g. a leader pic vs a grunt pic) — the rank is visible in the sprite before a single line of dialogue. The world side is `include/constants/flags.h`: `FLAG_HIDE_*_ROCKET` entries (e.g. `FLAG_HIDE_HIDEOUT_GIOVANNI 0x038`, `FLAG_HIDE_SILPH_ROCKETS 0x053`, `FLAG_HIDE_TOWER_ROCKET_1 0x05E`) — each flag is one "this Rocket is gone / this door is open" switch. Beating a Rocket in a tower sets a flag; the next Rocket's sprite appears or disappears because of that flag, not because a hierarchy table told it to.
- **HeartGold** (`pokeheartgold/include/constants/trainer_class.h`, `include/constants/trainers.h`, `src/trainer_data.c`): the cleanest example of the class-per-rank pattern. Grunts are `TRAINERCLASS_TEAM_ROCKET` (55) and `TRAINERCLASS_TEAM_ROCKET_F` (62). Executives are *separate classes with their own numbers*: `TRAINERCLASS_EXECUTIVE_ARIANA` (114), `TRAINERCLASS_EXECUTIVE_ARCHER` (116), `TRAINERCLASS_EXECUTIVE_PROTON` (117), `TRAINERCLASS_EXECUTIVE_PETREL` (118). The boss is `TRAINERCLASS_ROCKET_BOSS` (124). Each executive also gets *multiple trainer records* for rematches: `TRAINER_EXECUTIVE_ARIANA_ARIANA` (478) and `TRAINER_EXECUTIVE_ARIANA_ARIANA_2` (479), `TRAINER_EXECUTIVE_PETREL_PETREL` (487) and `TRAINER_EXECUTIVE_PETREL_PETREL_2` (488), `TRAINER_EXECUTIVE_PROTON_PROTON_2` (706). The `_2` record is a stronger party with the same class — that is how Pokemon does "the same admin, later, harder". `src/trainer_data.c` (`TrainerData_GetAttr`, `EnemyTrainerSet_Init`) reads a record by trainer ID and returns its class, party size, items, and AI flags — the battle engine never asks "what rank is this person in the hierarchy", it asks "what class is this record", and the class carries the rank.
- **Black 2** (`pokebw2/res/trainers/data/*.json`, `trainer.schema.json`): the data-first version of the same shape, which is the closest model for Mochiichao (because Mochiichao is a data-driven web game, not C). Each file is one trainer: `name`, `class` (e.g. `TRAINER_CLASS_TEAM_PLASMA_GRUNT_M` vs `TRAINER_CLASS_TEAM_PLASMA_GHETSIS` vs `TRAINER_CLASS_TEAM_PLASMA_COLRESS`), `battle_style`, `items`, `ai_flags` (grunts get `AI_FLAG_BASIC` + `AI_FLAG_TAG_STRATEGY`; a boss gets `AI_FLAG_BASIC` + `AI_FLAG_EVAL_ATTACK` + `AI_FLAG_EXPERT`), `money`, `party` (species + level + difficulty + ability + item + moves), and `messages` (typed slots, e.g. `TRMSG_LOSE`). Again: grunt, named officer, and boss are *different classes*, not one class with a rank number. The many numbered grunt files (`team_plasma_grunt.json`, `team_plasma_grunt_2.json`, … `_20.json`) are many separate records sharing one class — that is how Pokemon does "many grunts, one job".

### How the other factions fit the same shape (counts, for scale only)
Rocket: 4 executives (verified in HeartGold, above) + 1 boss, one region. Aqua: 2 admins + 1 leader, one region. Magma: 2 admins + 1 leader, one region. Galactic: 3 commanders (4 in Platinum) + 1 boss, one region. Plasma: 7 sages (a council, not field admins) + a separate 3-person shadow group + 1 boss, one region. Flare: 5 scientists + 1 boss, one region. Star: 5 bosses (one per base, no separate admin layer), one region. No Pokemon game puts 10 named mid-bosses in one region, and no Pokemon game spreads one faction's admins across 5 regions — because Pokemon games have 1 region each. Mochiichao's 10 is 2.5x Rocket's 4, which is why it only reads well spread out (see below), and why the code shape has to be extended, not copied whole.

### How Mochiichao's (b) structure maps onto that code shape
Structure (b), recommended by Coordinator B and accepted by Mars as "fine" in the 14:31 message (structure pick itself is still show-first until Mars locks it in this report's terms): **2 admins per Region 1–4 + 2 central/roving = 10.**
In Pokemon-code terms, that maps like this — and this is the part Mars asked "how does the code handle it" about:
- **One trainer class per admin rank, not one class for all 10.** Grunts: `SYNDICATE_GRUNT` (one class, many records, like Plasma's numbered grunt files). Admins: each admin gets their own class OR a shared `SYNDICATE_ADMIN` class with a per-record name/pic — HeartGold's model (a class per executive) is cleaner for Mochiichao because each admin has a distinct job (archivist, warden, smuggler, signal hijacker, fixer, engineer, public face, sampler, coordinator, hunter) and a distinct sprite. Either way, the class is where the rank lives; there is no separate "rank = 2" field to invent.
- **One trainer record per admin fight, plus a `_2` record for any rematch.** An admin's first fight and their later, harder fight are two records with the same class, exactly like Ariana / Ariana_2. Mochiichao's admin teams already grow (2 → 3 → 4 → 5 → 6 creatures, Lv24 → Lv76 across the arc) — in code that growth is either a bigger party in the same record (if the admin is fought once) or a `_2` record (if they return). The file that holds this is the Mochiichao equivalent of Black 2's `res/trainers/data/*.json`: one JSON record per admin, with `class`, `party`, `ai_flags` (Basic for early admins, Eval/Expert for late ones, matching Black 2's grunt-vs-boss AI gap), `reward`, and `messages` (intro/lose/after).
- **A region field + a roving flag, which Pokemon does not have and Mochiichao must add.** Pokemon's records have no "region" field because there is one region. Mochiichao's 10-admin structure needs two fields Pokemon never needed: `region` (1, 2, 3, 4, or null for central) and `roving` (true for the 2 central admins, false for the 8 regional ones). The 2 central admins (Cassian the coordinator, Soren the hunter, in the Coordinator B fill) are the ones whose `region` is null and whose appearance is gated by flags, not by town: Cassian appears at the Rift gate when the Region 4 arc is done, Soren appears wherever the Rift trail leads. That is the code version of "roving" — not a wandering NPC that walks the map, but a record whose spawn condition is a story flag rather than a town.
- **A chain of defeat flags, exactly like FireRed's `FLAG_HIDE_*_ROCKET`.** Beating Voss (Region 1 archivist) sets `defeatedAdminVoss`; that flag does three things: hides Voss's overworld sprite, unlocks the next Syndicate beat in Region 1 (Ferren, the warden), and counts toward the "admins beaten" total that gates the coordinator. Beating all 8 regional admins sets the flag that spawns the 2 central admins at the Rift gate. Beating the coordinator sets the flag that spawns the decoy (Jax) and, behind him, the real leader (Luigi). The hierarchy grunt → admin → coordinator → decoy → boss is therefore a *flag chain*, not a table: each link is one flag, each flag is set by one defeat, and the next link's sprite is hidden until its flag is set. That is precisely how FireRed hides Giovanni until the Silph/Rocket flags are set, extended from one region to five.
- **Why (b) works in code and (a)/(c) do not, in code terms.** (a) 2×5 regions would put 2 admin records in Region 5, where the Liberation Front already owns the faction layer — in code that means two factions' flag chains interleaving in the same towns, and the player (and the flag system) cannot tell which chain opened which door. (c) 5 pairs would require a "pair" field Pokemon never has, and would imply Aqua/Magma-style rivalry (two factions fighting each other) that does not exist in Syndicate canon — the code would have to invent a rivalry system to justify a field. (b) needs only the two fields above (region + roving) plus the flag chain Pokemon already has, so it is the smallest extension of the proven shape. That is why (b) is recommended: it is the least new code for the most story.
- **What does NOT change.** No Pokemon species, character, cry, sprite, music, or dialogue line is shipped. The trainer class constants, the record shape, the AI flag tiers, and the flag-chain gating are structure; the names (Voss, Ferren, Marlow, Tamsin, Corvin, Ilsa, Aldous, Mireille, Cassian, Soren), the teams (Mochiichao species IDs and levels), the towns, and the dialogue are all Mochiichao. A Mochiichao admin record looks like a Black 2 trainer JSON in shape and like nothing in Black 2 in content.

### One-sentence version for Mars
Pokemon code does not have an "admins" list — it has a job class per rank, one fight record per admin (with a harder second record if they come back), and a chain of "you beat this person, so that door opens" flags — and Mochiichao's 10 admins fit that shape by adding only a region field and a roving flag, with the 8 regional admins gated by their own region's flags and the 2 central admins gated by "you beat all 8", which is how the coordinator and the hunter end up at the Rift gate at the end instead of in a town at the start.
