# Cry method — 60% Mochiichao way (main), 40% Pokemon way

Blend rule (Mars, standing): Mochiichao's way of making cries is the
MAIN way (60%). Pokemon's way is 40%. 100% of Pokemon's cry SYSTEM is
pulled, ZERO Pokemon audio is copied, sampled, or used as a base.

## The Pokemon system pulled (40%) — verified from decomp files

Read, not guessed, from `~/workspace/mochiichao-work/fresh-start/`:

- FireRed `pokefirered-leafgreen/sound/cry_tables.inc`: `gCryTable`,
  one `cry Cry_<Species>` entry per species, in species order.
- FireRed `src/data/pokemon/cry_ids.h`: species -> cry ID mapping, so
  playback is always species-indexed, never by filename guesswork.
- FireRed playback API, used everywhere a creature speaks: 
  `PlayCry_Normal(species, ...)` and
  `PlayCry_NormalNoDucking(species, pan, volume, CRY_PRIORITY_*)`
  (priority: normal, ambient, etc.). Same call sites in battle,
  Pokedex, evolution, field, credits, hall of fame, intro speech —
  one cry per species, reused across every context.
- HeartGold: `PlayCry(species, form)` / `PlayCryEx(..., pan, volume,
  ...)` — same species-indexed API on DS, with form support.
- Title press timing, FireRed `src/title_screen.c`, Cry scene:
  press -> `PlayCry_Normal(TITLE_SPECIES, 0)` (line 715), 90-frame
  wait (1.5 seconds at 60 fps), white palette fade, BGM fade out.
  HeartGold `src/title_screen.c` does the same shape: PlayCry +
  white fade + BGM fade.
- GBA cries are data-driven sound-engine parameters; DS cries are
  sampled audio played through the same species-indexed API. The
  SYSTEM taken from both is: table + ID mapping + API + timing +
  reuse across title/battle/lab. No waveform, sample, or cry audio
  data was taken from either.

What Mochiichao takes from that 40%: one cry per species in a table,
indexed by species (roster order 001-046 + 331, not filename luck);
playback with pan/volume/priority parameters; title press -> cry ->
~1.5s wait -> white fade -> BGM fade; and the same single file reused
for title, battle, and lab, exactly like Pokemon reuses one cry in
battle, Pokedex, evolution, and field.

## The Mochiichao way (60%, main) — and how it is better

Original procedural synthesis per creature canon, built with Python
(numpy oscillators, filtered noise, envelopes) in
`synth-all-47-20261026.py` (deterministic: noise seeded per creature
name, so reruns reproduce the same cry). Each cry is a unique layered
design: a fundamental pitch glide + harmonics + an element texture
layer, shaped by an attack/decay envelope per creature size and
personality. Element textures used:

- Water: sine bloop + bubble pops. Chrome: metallic inharmonic
  partials + jaw snap. Core/Earth: low sine + brown-noise rumble.
  Flame: warm harmonics + crackle bursts. Beast/Normal-equivalent:
  animal vocal chirp/growl with vibrato. Flora/Grass-equivalent:
  soft trill + leaf rustle. Bug/Silk: high flutter trill. Aero/Wind:
  airy gust sweep. Umbral: breathy whisper, long decay. Strike:
  punchy shout + thump. Mythic: chime arpeggio, long ring. Neon:
  cosmic-glow shimmer (proposal timbre only, type open).

Better than Pokemon in these specific ways, and only these:

1. NOT pitch-shifted copies of one base sound. GBA cries reuse a
   small set of waveforms with pitch/parameter changes per species;
   every Mochiichao cry here is designed per creature from its own
   element, tags, and size — 47 distinct parameter sets, not 47
   transpositions of one cry.
2. Modern fidelity. GBA output is limited-channel, low-rate,
   effectively mono game audio. These are stereo 16-bit PCM WAV at
   44100 Hz, full-range, with clean envelopes and no clipping
   (normalised to 0.89 peak), so a large creature and a tiny sprite
   do not sound like the same chip at different pitches.
3. Expressive per-creature envelopes. Attack and decay follow size
   and personality (tiny creatures: fast attack, short decay;
   ghosts and legendaries: slow attack, long ring-out; large
   creatures: swell attack, heavy decay), instead of one fixed
   cry envelope shape.
4. Element textures are audible, not implied. Water actually
   bubbles, fire actually crackles, earth actually rumbles, metal
   actually pings — the element is in the sound, not only in the
   creature's type label.

What is NOT claimed as better: Pokemon's cry system design (table,
API, timing, reuse) is kept whole at 40% precisely because it works.
The improvement is in sound design and fidelity, not in replacing
a working system with an invented one.

## Production facts (staged, 2026-10-26)

- Script: `synth-all-47-20261026.py` in this same `work/cries/`
  folder. Output: `audio/<name-lower>-cry.wav`, 47 files.
- Format: 16-bit PCM stereo WAV, 44100 Hz, one-shot, 1.20-2.00s
  (nominally 1.5s). Verified: all 47 exist, all in duration range,
  all non-silent (RMS 0.14-0.34 in the synth run), no failures.
- No Pokemon audio, no copied samples, no recorded Pokemon sounds,
  no hand-recorded voice lines. Western Heart Dorowani voice lines
  (Japanese word-bursts) were NOT recorded or synthesised into any
  cry — see the expanded spec for why that voice direction is kept
  separate from the non-verbal cry.
- Ship step (NOT done here): after Mars hears and approves the
  staged WAVs in words, a gate-checked PR moves approved files to
  `public/audio/cries/<name>-cry.wav` with TitleScene cry-gate
  wiring (pan/volume/priority parameters, title press -> cry ->
  1.5s wait -> white fade). Until then, staged only.
